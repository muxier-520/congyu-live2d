## 第7章 继承和接口

### 7.1 了解继承

#### 知识点讲解

- **继承的含义**  
  继承允许一个类（衍生类/子类）获得另一个类（基类/父类）的成员（字段、属性、方法等），并可扩展或修改这些成员。  
  目的：代码复用、建立类型层次、支持多态。

- **UML表示**  


- **特化（Specialization）与通化（Generalization）**  
  - **特化**：子类是父类的更具体版本（如 `Student` 是 `Person` 的特化）。  
  - **通化**：父类是子类的通用抽象（如 `Person` 是 `Student` 的通化）。  
  - 关系描述：子类 **is a** 父类（“是一种”关系）。

- **组合关系（has-a）**  
  一个类包含另一个类的实例作为成员，如 `Computer` 包含 `CPU`。不是继承，而是组装。

- **为什么需要继承**  
  - 减少重复代码，提高复用性  
  - 便于系统扩展和维护  
  - 实现多态的基础

#### 易错点

- 混淆 **is-a** 与 **has-a**：`Car` 继承 `Vehicle` 是 is-a；`Car` 包含 `Engine` 是 has-a。  
- 误以为子类可以继承父类的**构造函数和析构函数** —— 实际上不能继承，但可以通过 `base` 调用。

#### 题目案例

> **选择题**  
> 1. 下列哪一组关系属于“is-a”关系？  
>    A. `Book` 与 `Page`  
>    B. `Teacher` 与 `Person`  
>    C. `House` 与 `Door`  
>    D. `Car` 与 `Wheel`  
>    **答案**：B

> **填空题**  
> 2. 在继承关系中，子类 _____ 父类的构造函数。  
>    **答案**：不能继承（或“不继承”）。

### 7.2 单一继承机制

#### 知识点讲解

- **C# 是单一继承**：一个类只能直接继承一个基类（单亲），可通过接口实现多接口。

- **继承语法**  
  ```csharp
  class 子类 : 基类 { ... }
  ```

- **存取修饰词对继承的影响**  

  | 修饰词      | 子类访问性                         |
  |-------------|------------------------------------|
  | `public`    | 可访问                             |
  | `protected` | 可访问（但非派生类不可）           |
  | `private`   | **不可访问**                       |
  | `internal`  | 同一程序集内可访问（跨程序集不可） |

- **`base` 关键字**  
  - 在子类中调用父类的构造函数：`public Child() : base(参数)`  
  - 调用父类已被覆盖的成员：`base.Method()`  
  - **不能在静态方法中使用 `base`**。

- **`this` 关键字**  
  - 指向当前对象实例，可用于区分成员变量与局部变量（`this.name = name`）。  
  - 也可用作索引器（`this[int index]`）。

- **`new` 修饰符**  
  - 用于在子类中**显式隐藏**从父类继承的同名成员（方法、属性、字段等）。  
  - 如果不写 `new`，编译器会警告，但仍可隐藏。

#### 易错点

- 误以为 `base` 可以调用父类的 `private` 成员 → 不可以。  
- 忘记在子类构造函数中使用 `base` 调用父类带参数的构造函数，导致编译错误（如果父类没有无参构造）。  
- 滥用 `new` 隐藏父类方法，破坏多态预期。

#### 题目案例

> **代码问答题**  
> 3. 阅读以下代码，写出输出结果。  
> ```csharp
> class Parent {
>     public virtual void Show() { Console.WriteLine("Parent"); }
> }
> class Child : Parent {
>     public new void Show() { Console.WriteLine("Child"); }
> }
> class Program {
>     static void Main() {
>         Parent p = new Child();
>         p.Show();
>     }
> }
> ```
> **答案**：`Parent`（因为 `new` 不会覆写，通过父类引用调用时仍执行父类方法）。

> **填空题**  
> 4. 子类构造函数若要调用父类带参数的构造函数，需使用 _____ 关键字。  
>    **答案**：`base`

### 7.3 探讨多型（多态）

#### 知识点讲解

- **多态概念**：同一个名称，不同实现（“同名异式”）。  
  分为**编译时多态**（方法重载）和**运行时多态**（`virtual/override` 和接口）。

- **方法重载（Overload）**  
  - 同一类中多个同名方法，参数列表不同（类型、个数、顺序），与继承无关。

- **方法覆写（Override）**  
  - 子类重新实现父类中用 `virtual` 或 `abstract` 标记的方法。  
  - 要求完全相同的签名和返回类型，使用 `override` 关键字。

- **`virtual` 与 `override` 规则**  
  - 基类方法标记为 `virtual`，子类可选 `override`。  
  - 子类 `override` 的方法仍是 `virtual` 的，可继续被后代覆写。  
  - 静态方法、私有方法不能覆写。  
  - 覆写不能改变访问级别（一般保持 `public`）。

- **`new` 隐藏 vs `override` 覆写**  
  - `override`：参与多态，通过父类引用调用时执行子类实现。  
  - `new`：不参与多态，通过父类引用调用时执行父类实现。

- **多态的实现**  
  - 父类引用指向子类对象，调用 `virtual` 方法时动态决定调用哪个版本。  
  - 接口引用指向实现类的对象，调用接口方法时动态调用实现类的版本。

#### 易错点

- 混淆重载（overload）与覆写（override）。  
- 忘记在基类方法上加 `virtual` 就直接想在子类用 `override`（会编译错误）。  
- 误以为 `override` 可以改变方法的访问修饰符。  
- 错误地认为 `new` 和 `override` 可以同时使用（不能）。

#### 题目案例

> **选择题**  
> 5. 关于 `override` 和 `new` 的说法，正确的是：  
>    A. 使用 `override` 的方法可以改变返回类型。  
>    B. 使用 `new` 的方法可以改变参数列表。  
>    C. `override` 方法可以在基类引用上体现多态。  
>    D. `new` 方法可以同时和 `virtual` 一起使用。  
>    **答案**：C

> **代码填空题**  
> 6. 补全代码，使得输出 “Bark”。  
> ```csharp
> class Animal {
>     public ______ void Sound() { Console.WriteLine("?"); }
> }
> class Dog : Animal {
>     public ______ void Sound() { Console.WriteLine("Bark"); }
> }
> // Main中：Animal a = new Dog(); a.Sound();
> ```
> **答案**：`virtual` 和 `override`

### 7.4 接口和抽象类

#### 知识点讲解

- **抽象类（abstract class）**  
  - 使用 `abstract` 关键字修饰，**不能实例化**，只能被继承。  
  - 可包含抽象方法（无方法体，必须由子类实现）和具体方法。  
  - 抽象方法隐式为 `virtual`，子类必须用 `override` 实现。  
  - 如果子类不是抽象类，则必须实现所有抽象成员。

- **密封类（sealed class）**  
  - 使用 `sealed` 关键字修饰，不能被继承。  
  - 可同时用于方法（`sealed override` 表示该方法不能再被子类覆写）。

- **接口（interface）**  
  - 使用 `interface` 关键字，只包含方法、属性、事件、索引器的声明。  
  - **不能包含字段、构造函数、析构函数、运算符、常量**。  
  - 成员默认 `public`，**不能加访问修饰符**。  
  - 一个类可实现**多个接口**（弥补单继承不足）。  
  - 接口可继承其他接口。

- **抽象类 vs 接口**  

  | 特性         | 抽象类                          | 接口                          |
  |--------------|---------------------------------|-------------------------------|
  | 实例化       | 不能                            | 不能                          |
  | 字段         | 可以有                          | 不能有                        |
  | 构造函数     | 可以有                          | 不能有                        |
  | 方法实现     | 可以有具体方法                  | 只能声明，不能实现            |
  | 继承数量     | 一个类只能继承一个抽象类        | 一个类可实现多个接口          |
  | 访问修饰符   | 可以使用各种修饰符              | 成员默认 public，不能加修饰符 |

- **通过接口实现多态**：不同类实现同一接口，通过接口引用可调用各自实现。

#### 易错点

- 抽象类中如果有一个抽象方法，类必须标记为 `abstract`。  
- 接口中的方法不能加 `public`，但实现类中必须显式声明为 `public`。  
- 错误地尝试实例化接口或抽象类。  
- 实现接口时，忘记实现所有成员会编译错误。

#### 题目案例

> **判断题**  
> 7. 抽象类中不能包含具体方法的实现。 （ ）  
>    **答案**：错误（可以包含具体方法）。

> **简答题**  
> 8. 简述抽象类与接口的三大主要区别。  
>    **答案示例**：  
>    - 抽象类可以有字段和构造函数；接口不能。  
>    - 一个类只能继承一个抽象类；可实现多个接口。  
>    - 抽象类中的方法可以用 `virtual`/`override` 控制；接口中的方法默认是抽象的，必须在实现类中实现。

> **代码设计题**  
> 9. 定义接口 `IMovable`，包含方法 `Move()`。让 `Car` 和 `Person` 类实现该接口，并各自输出不同信息。写出代码。  
>    **答案示例**：
>    ```csharp
>    interface IMovable { void Move(); }
>    class Car : IMovable { public void Move() { Console.WriteLine("Car moves"); } }
>    class Person : IMovable { public void Move() { Console.WriteLine("Person walks"); } }
>    ```

## 第8章 泛型和集合

### 8.1 浅谈集合

#### 知识点讲解

- **集合概念**：用于存储和管理一组对象的容器（如数组、列表、字典等），可通过索引或键访问元素。

- **非泛型集合（命名空间 `System.Collections`）**  
  - `ArrayList`：动态数组，元素为 `object`，可添加任意类型 → 装箱拆箱，类型不安全。  
  - `Hashtable`：键值对，键和值均为 `object`。  
  - `SortedList`：排序的键值对。  
  - `Queue`：队列，FIFO（先进先出），主要方法 `Enqueue()`、`Dequeue()`。  
  - `Stack`：栈，LIFO（后进先出），主要方法 `Push()`、`Pop()`。

- **泛型集合（命名空间 `System.Collections.Generic`）**  
  - `List<T>`：动态数组，类型安全，无需装箱。  
  - `Dictionary<TKey, TValue>`：键值对，泛型。  
  - `Queue<T>`、`Stack<T>`：泛型版本。  
  - 优点：类型安全，性能更高（无装箱拆箱）。

- **`IList` 和 `IDictionary` 接口**  
  - `IList`：表示可索引访问的集合（如数组、列表）。  
  - `IDictionary`：表示键值对集合。

- **`ArrayList` vs `List<T>`**：`ArrayList` 是旧版，容易出错；`List<T>` 是推荐使用的泛型替代。

#### 易错点

- 忘记引入命名空间 `System.Collections.Generic` 就使用 `List<T>`。  
- 从 `ArrayList` 取值后忘记强制类型转换导致运行时异常。  
- 混淆 `Queue` 和 `Stack` 的存取顺序。

#### 题目案例

> **选择题**  
> 10. 下列哪个集合类允许存储不同类型的元素而不需要强制转换？  
>     A. `List<int>`  
>     B. `ArrayList`  
>     C. `Dictionary<string, int>`  
>     D. `Stack<double>`  
>     **答案**：B（但注意使用时需要转换，实际上B存储object，但不需要转换即可存入，取出需转换；泛型类不允许不同类型存入。标准答案是B）

> **填空题**  
> 11. `Queue` 的取数据方法是 ____，`Stack` 的取数据方法是 ____。  
>     **答案**：`Dequeue`，`Pop`

> **代码填空题**  
> 12. 补全代码，创建一个存储字符串的队列，并依次取出所有元素。  
> ```csharp
> Queue<string> q = new Queue<string>();
> q.______("A"); q.______("B");
> while(q.Count > 0) {
>     Console.WriteLine(q.______());
> }
> ```
> **答案**：`Enqueue`，`Enqueue`，`Dequeue`

### 8.2 建立泛型

#### 知识点讲解

- **泛型是什么**  
  使用类型占位符 `<T>` 定义类、方法、接口、委托等，在使用时指定具体类型。编译时替换为实际类型，提供类型安全和代码复用。

- **泛型方法**  
  ```csharp
  static void Swap<T>(ref T a, ref T b) { T temp = a; a = b; b = temp; }
  ```
  调用时可显式指定类型参数：`Swap<int>(ref x, ref y)`，也可类型推断。

- **泛型类**  
  ```csharp
  class Stack<T> {
      private T[] items;
      public void Push(T item) { ... }
      public T Pop() { ... }
  }
  ```
  使用：`Stack<int> s = new Stack<int>();`

- **泛型约束（常见补充）**  
  `where T : class`（引用类型），`where T : struct`（值类型），`where T : new()`（有无参构造）等。

#### 易错点

- 尝试对泛型类型进行 `typeof(T)` 等操作时需谨慎。  
- 泛型类中的静态成员在不同封闭类型间是独立的（每个具体类型有自己的静态成员）。

#### 题目案例

> **代码填空题**  
> 13. 编写一个泛型方法 `GetMax<T>`，返回两个值中较大的一个（假设 T 实现了 `IComparable`）。  
> ```csharp
> static T GetMax<T>(T a, T b) where T : IComparable {
>     return a.CompareTo(b) > 0 ? a : b;
> }
> ```

> **判断题**  
> 14. 泛型方法 `void F<T>(T t)` 可以同时接受 `int` 和 `string` 作为类型参数。 （ ）  
>     **答案**：正确。

### 8.3 委派（委托）

#### 知识点讲解

- **委托概念**：委托是一种类型，它封装了方法的签名（参数+返回值），可以像变量一样引用方法。相当于“方法的指针”或“回调的容器”。

- **声明、实例化和调用**  
  ```csharp
  public delegate void MyDelegate(string msg);   // 声明
  static void Show(string s) { Console.WriteLine(s); }
  MyDelegate d = Show;   // 实例化
  d("Hello");            // 调用
  ```

- **多播委托**  
  - 使用 `+=` 组合多个方法，使用 `-=` 移除。  
  - 调用时会依次执行所有注册的方法。  
  - 如果方法有返回值，多播返回最后一个方法的返回值。

- **委托作为参数**：可以将方法封装成委托传递给其他方法，实现回调。

- **泛型委托**  
  - 系统预定义：`Action`（无返回值）、`Func<TResult>`（有返回值）、`Predicate<T>`（返回bool）。  
  - 可自定义泛型委托：`delegate T MyDel<T>(T a, T b);`

- **委托数组**：将多个委托放入数组，可以随机或顺序调用。

#### 易错点

- 忘记初始化委托就调用 → `NullReferenceException`。  
- 多播委托中某个方法抛出异常会中断后续调用。  
- 混淆 `Action` 和 `Func` 的使用场景。

#### 题目案例

> **选择题**  
> 15. 现有委托声明 `delegate int Calc(int x, int y);`，以下哪个方法可以赋给该委托？  
>     A. `void Add(int a, int b)`  
>     B. `int Sum(int a, int b, int c)`  
>     C. `int Multiply(int a, int b)`  
>     D. `double Divide(int a, int b)`  
>     **答案**：C

> **代码填空题**  
> 16. 使用匿名方法或Lambda表达式将委托 `d` 指向一个输出字符串长度的方法。  
> ```csharp
> delegate void StringDelegate(string s);
> StringDelegate d = ______;
> ```
> **答案**：`s => Console.WriteLine(s.Length)` 或 `delegate(string s){Console.WriteLine(s.Length);}`

> **简答题**  
> 17. 简述委托的常见应用场景。  
>     **答案**：事件驱动、回调函数、LINQ（`Where` 等接受委托）、多线程（`Thread` 接受委托）、策略模式等。

## 第9章 错误和例外处理

### 9.1 Visual Studio 侦错环境

#### 知识点讲解

- **两种侦错模式**

  - **监看式**：手动添加要监视的变量或表达式。  
  - **自动变量**：自动显示当前行和上一行使用的变量。

- **错误列表窗口**  
  - **错误**：编译错误，必须修复。  
  - **警告**：不影响编译，但提示潜在问题。

#### 易错点

- 混淆 F10 和 F11 的作用。  
- 忘记在调试模式下查看变量（非调试模式变量窗口为空）。

#### 题目案例

>     **答案**：F9

### 9.2 常见的错误类型

#### 知识点讲解

- **语法错误**：编译时被发现，如漏分号、未声明变量、圆括号不匹配等。  
- **运行时错误（例外）**：程序语法正确，但执行时出错，如除以零、数组越界、空引用、文件找不到等。

#### 易错点

- 将逻辑错误误认为是运行时异常，两者不同。

### 9.3 例外状况的处理

#### 知识点讲解

- **结构化例外处理**：使用 `try`、`catch`、`finally`、`throw` 语句。

- **异常类层次**  
  - `System.Exception` 为所有异常的基类。  
  - `SystemException`：CLR 抛出的异常（如 `DivideByZeroException`， `IndexOutOfRangeException`， `NullReferenceException`）。  
  - `ApplicationException`：用户自定义异常的基类（建议继承自 `Exception` 而非 `ApplicationException`）。

- **`try-catch` 语法**  
  ```csharp
  try {
      // 可能引发异常的代码
  }
  catch (DivideByZeroException ex) {
      // 处理除以零
  }
  catch (Exception ex) {
      // 处理其他异常
  }
  ```

- **多重 catch**：按继承顺序从具体到一般排列（先子类后父类），否则编译错误。

- **`finally` 块**：无论是否发生异常，都会执行（除非进程被强制终止）。通常用于释放资源（关闭文件、数据库连接等）。

- **`throw` 语句**  
  - 主动抛出异常：`throw new Exception("错误消息");`  
  - 可重新抛出：`throw;`（保留原始堆栈信息）。

- **常用异常属性**：`Message`、`StackTrace`、`InnerException`。

#### 易错点

- catch 顺序错误：将 `catch(Exception ex)` 放在前面会导致后面具体 catch 永远执行不到。  
- 滥用 `catch(Exception)` 而不处理或重抛，隐藏错误。  
- 忘记 `finally` 中释放非托管资源（虽然 C# 有 using，但有时需要手动）。
